# RoleCallAI Secure Admin, RAG, and Automatic Runtime Specification

Status: approved for implementation, cloud provisioning, migration, deployment, and verification.

## Product goal

RoleCallAI remains a reusable English, voice-only meeting facilitator for 2–10 participants, 5–60 minute meetings, one active occurrence per room, and five concurrent ten-person rooms. This release adds a shared secured admin workspace, recoverable encrypted participant links, room documents grounded through Firestore-vector RAG, and a 30-minute idle suspend/wake lifecycle.

The existing Gemini models, deterministic floor controller, LiveKit bridge, role presets, memory workflow, retention, privacy boundaries, named Firestore database `rolecall-dev`, and `europe-west4` data residency remain unchanged.

## Authentication and administration

- The public home page shows the product introduction and a single shared admin login. Unauthenticated clients cannot list, create, update, delete, end, or inspect rooms.
- Generate a random `judge-<suffix>` username and 24-character password. Store the username, Argon2id hash, and credential version in regional Secret Manager; reveal plaintext once during rotation.
- Every login requires a valid reCAPTCHA Enterprise checkbox assessment for the configured hostname and action. Use Firestore-backed IP/network throttles because GKE Redis can be asleep.
- Successful login creates an eight-hour Secure, HttpOnly, SameSite session backed by a Firestore TTL record. Credential-version rotation invalidates existing sessions.
- State-changing admin requests require the admin session plus same-origin/CSRF validation.
- One authenticated dashboard lists every room owned by `shared-demo-admin`, participant links, documents, active occurrence, history, transcripts, recaps, and runtime state.
- Remove admin capability links, admin digests/sessions, `/manage/{roomId}` management, and browser link-vault discovery. Legacy manage links scrub fragments and redirect home.
- Participant seat capabilities remain. Admin and participant cookies use separate names.

## Room and seat migration

- Assign every existing room `owner_id=shared-demo-admin` while no occurrence is active.
- Rotate every participant capability transactionally. Old links and sessions become invalid.
- Persist a SHA-256 digest for verification, Cloud KMS ciphertext for authenticated recovery, and capability version for regeneration/revocation.
- Participant links are decrypted only by an explicit authenticated endpoint, returned with `Cache-Control: no-store`, and excluded from logs and telemetry.

## Document library and Firestore-vector RAG

- Support searchable PDF, DOCX, PPTX, TXT, and Markdown. Reject scans without text, encrypted/macro documents, MIME/signature mismatches, and empty extraction.
- Limits: 25 MB/file, 20 active files and 200 MB/room, 500 pages/slides, and one million extracted characters.
- Stream uploads to a private regional GCS bucket using immutable room/document/version object paths.
- An OIDC-authenticated Pub/Sub push invokes a min-zero Cloud Run indexer with retry and dead letter handling. Indexing validates and scans, extracts text, creates deterministic chunks at approximately 800 tokens/120 overlap, embeds with `gemini-embedding-001` at 768 dimensions, and stores vectors plus sanitized citation metadata in `rolecall-dev`.
- Firestore vector queries are server-scoped to the current room and active ready versions. A replacement becomes active only after successful indexing; failed replacement leaves the previous version active.
- Document mutation is disabled during an active occurrence. Pending or failed documents do not block a meeting; the occurrence snapshots only ready versions and exposes an omission warning.
- Add the server-scoped ADK function `search_room_docs(query)`. The model never supplies room, occurrence, corpus, or version identifiers.
- Retrieved documents are untrusted evidence, never instructions. Return at most five sanitized excerpts with title, version, page/slide range, and score. Attach citations to relevant captions and recaps; participants cannot download originals.
- Documents, chunks, and originals expire after 90 days or earlier deletion.

## Runtime sleep and wake

- Keep the existing same-origin Cloud Run web/bootstrap service public with `min_instances=0`; login, dashboard, room CRUD, and document indexing work without GKE.
- Runtime states: `SLEEPING`, `WAKING`, `READY`, `SUSPENDING`, `ERROR` with progress and timestamps in Firestore.
- Only a logged-in admin may request wake. Participant join returns typed `runtime_asleep` without creating an occurrence or waking infrastructure.
- Real authenticated interactions, participant lobby operations, or voice activity update a debounced activity lease. A passive visible tab does not.
- Every five minutes, Cloud Scheduler invokes an OIDC-authenticated idle check. After at least 30 minutes and no live occurrence, it atomically dispatches an idempotent suspend job.
- Suspend blocks joins, deprovisions LiveKit/TURN load-balancer services while retaining reserved IPs, suspends autoscalers/disruption budgets, scales workloads down, disables node autoscaling, and resizes both GKE pools to zero.
- Replace Memorystore Basic with one ephemeral authenticated Redis pod on the worker pool. Firestore holds durable security/rate state.
- Wake restores two worker nodes and one media node, Redis, ingress/TLS/load balancers, one LiveKit pod, two ADK workers, health checks, and autoscaling ceilings of three media nodes/six workers. Target wake time is 10–20 minutes.
- Cloud Run, Firestore, GCS, Secret Manager, KMS, Scheduler, Pub/Sub, Artifact Registry, GKE control plane, and reserved IP storage/control resources remain provisioned; only request-driven operations and unavoidable fixed control-plane/IP costs remain at idle.

## API contract

- Auth: `POST /v1/auth/login`, `GET /v1/auth/session`, `POST /v1/auth/logout`.
- Runtime: `GET /v1/runtime`, `POST /v1/runtime:wake`, `POST /v1/runtime/activity`.
- Admin rooms: `GET|POST /v1/admin/rooms`, `GET|PATCH|DELETE /v1/admin/rooms/{roomId}`, `GET /v1/admin/rooms/{roomId}/seat-links`, plus admin-scoped regeneration, end permission, end meeting, history, and transcript routes.
- Documents: `GET|POST /v1/admin/rooms/{roomId}/documents`, `DELETE .../{documentId}`, `POST .../{documentId}:retry`, `POST .../{documentId}:replace`.
- Participant capability exchange/join/refresh/leave/start/recap routes remain, using the participant cookie. Join returns HTTP 503 with `runtime_asleep` while unavailable.
- Add `RuntimeStatus`, `AdminSession`, `DocumentStatus`, `DocumentVersion`, `RetrievalCitation`, occurrence `ready_document_version_ids`, and recap `citations`.
- Remove `RoomCreated.admin_url`, dashboard capability request types, and admin capability claims.

## Security and privacy

- No credential, token, decrypted link, document text/excerpt, prompt, transcript, or raw audio in logs, traces, build output, Git, or analytics.
- Password verification is constant-response and Argon2id-backed. Login/wake/upload endpoints have durable limits. Sessions and counters use TTL.
- KMS decryption is available only to the control service; indexer has least-privilege object-read, vector-write, and embedding access.
- Validate host/action/risk on reCAPTCHA assessments, use strict CSP/headers, origin checks, and no-store responses.
- Preserve no raw audio, no LiveKit egress, finalized-transcript-only persistence, disabled GenAI content capture, and 90-day consent disclosure.

## Deployment and verification

- Define all new services, IAM, KMS, reCAPTCHA, GCS, Pub/Sub/DLQ, Firestore vector indexes, Cloud Run indexer/runtime jobs, in-cluster Redis, and Scheduler in the existing custom Terraform.
- Deployment is staged: validate/test; review saved Terraform plan and cost; apply infrastructure; deploy backward-compatible images; confirm no active meetings; export a Firestore backup; generate credentials; migrate owners and rotate seats; remove legacy admin behavior; wake; run smoke/eval/load checks; return to `SLEEPING`.
- Unit and integration tests cover auth, CAPTCHA, sessions, throttling, CSRF, migration, KMS links, document validation/extraction/chunking, vector isolation, citations, activity debounce, and runtime races.
- Browser tests cover protected creation, login, dashboard, documents, sleeping participant behavior, wake progress, mobile and accessibility.
- Agent eval adds grounded document use, no-match behavior, prompt injection, citations, and cross-room isolation while preserving the existing role/floor quality threshold.
- Acceptance includes zero unauthorized admin access, revoked legacy seat links, zero cross-room retrieval, GKE node count zero after 30–35 idle minutes, participant no-wake, admin wake within 20 minutes, five-room capacity, and a clean secret scan.

## Studied recipes and intended reuse

- `core/python/rag-vector-search`: deterministic chunk IDs, write/read schema symmetry, `RETRIEVAL_DOCUMENT` versus `RETRIEVAL_QUERY`, bounded top-k retrieval, idempotent ingestion, and explicit no-match handling. Replace Vector Search/KFP/BigQuery with the approved GCS + Cloud Run + Firestore vector pipeline.
- `core/python/ambient-expense-agent`: OIDC-authenticated Pub/Sub push, 600-second acknowledgement, exponential retry, dead-letter after five attempts, deterministic code-owned routing, and idempotent server-side event handling.
- Existing RoleCallAI samples remain applicable for `Runner.run_live`, Memory Bank, and post-meeting Workflow behavior.

## Lyria lobby soundtrack amendment

- Generate one shared warm ambient track with `lyria-3-pro-preview` using one
  fixed, non-personal prompt at the model's global endpoint. No participant,
  room, transcript, document, instruction, or meeting audio enters that call.
- Require dry-run, exact `$0.08` cost confirmation, MPEG validation, immutable
  output protection, and sanitized provenance. The MP3 is a versioned build
  asset; there are no runtime Lyria calls.
- Attempt low-volume playback only after a successful participant join while
  the occurrence is `LOBBY`. Provide accessible Play/Mute, remember only local
  mute preference, and fade/stop before `STARTING` or on disconnect/unmount.
- Music never publishes to LiveKit, persists as meeting data, enters ADK/Gemini,
  appears in telemetry, or counts as runtime activity. Failure/autoplay denial
  cannot block joining or starting.
- Public requirements and test traceability live under `docs/specs/`.
