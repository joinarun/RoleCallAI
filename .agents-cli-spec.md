# RoleCallAI Phase 1 Specification

Status: approved for implementation and local validation. Cloud provisioning and deployment require a separate explicit approval after review of the Terraform plan and cost estimate.

## Product goal

RoleCallAI is a reusable, browser-based voice meeting room in which a named AI facilitator runs a timed meeting for 2-10 human participants. It includes twelve trusted facilitator presets plus a custom role, addresses participants by persistent seat identity, enforces a deterministic speaking floor, and recalls prior room outcomes.

Phase 1 is English-only, voice-only, supports 5-60 minute meetings, one active occurrence per reusable room, and a development load target of five concurrent ten-person rooms. There is no account authentication; unguessable capability links are credentials.

## Approved stack and location

- React, Vite, and TypeScript for the admin and participant SPA.
- FastAPI and Google ADK 2.x for the API, live agent, and post-meeting workflow.
- Self-hosted LiveKit on GKE Standard for WebRTC and server-enforced publishing permissions.
- Gemini Live model `gemini-live-2.5-flash-native-audio` for voice.
- Gemini model `gemini-3.7-flash` on the Vertex AI `eu` multi-region endpoint for summaries and evaluation.
- A locally configured Google Cloud project; application resources and product data reside in `europe-west4`, while summary/evaluation inference remains EU-scoped through the `eu` endpoint.
- Named Firestore Native database `rolecall-dev`; never modify an existing `(default)` database.
- Cloud Run for the same-origin SPA/API plus post-processing endpoints, GKE for LiveKit and meeting workers, Pub/Sub, Secret Manager, Memorystore Redis, Agent Platform Sessions/Memory Bank, Cloud Trace/Logging/Monitoring.
- Private source control is permitted. No staging environment or CI/CD in phase 1.

## Capability and privacy boundaries

- Create one admin capability and one persistent capability per seat. URLs use fragments: `/manage/{roomId}#cap={token}` and `/join/{roomId}#cap={token}`.
- Exchange a fragment once for a short-lived Secure, HttpOnly, SameSite cookie and remove the fragment from browser history. Persist SHA-256 token digests only.
- Regenerating a seat capability revokes the old capability and its sessions. Prevent concurrent use of the same seat.
- No global room list or capability recovery.
- No raw audio persistence, LiveKit egress, ADK live-blob persistence, prompt/content telemetry, or BigQuery analytics. Persist finalized transcript segments only.
- Participants consent to Gemini processing and 90-day retention before joining. Participants can access recaps they attended; only the admin can access complete history/transcripts.

## Room lifecycle

- Room creation captures Unicode-normalized case-insensitively unique name, participant count, duration, role, agent name, instructions, and optional Fun Friday game.
- Phase 1 intentionally has no document library, file upload, citation, or RAG capability.

## Meeting lifecycle and deterministic controller

States: `LOBBY -> STARTING -> RUNNING -> ENDING -> PROCESSING -> COMPLETED`; unrecoverable worker/agent failures enter `FAILED` after partial post-processing.

- First valid arrival transactionally creates the next occurrence.
- Auto-start when all expected seats are present; after two minutes any present participant may start and absentees are skipped.
- Late arrivals enter the remaining turn order. Hold a disconnected speaker's floor for 30 seconds, then skip. If the live agent cannot recover within 60 seconds, finish and post-process the partial meeting.
- Participants may intentionally leave immediately. The admin may end an occurrence for everyone and may grant or revoke that narrow capability for individual persistent seats, including during an active occurrence.
- Controller, never the model, owns lifecycle, timer, floor, permissions, and turn order.
- Only the floor owner can publish audio in LiveKit. The floor owner may interrupt the agent; everyone else raises a hand over versioned data messages.
- Every human-to-human rotation passes through an agent-owned handoff. `advance_floor` selects `nextFloorSlotId`; the agent acknowledges the completed turn before `give_floor` opens the selected microphone.
- Wrap up two minutes before the configured end and enforce a 60-second closing grace.

Server-scoped, idempotent agent tools: `get_meeting_state`, `set_phase`, `give_floor`, `advance_floor`, `record_outcome`, `get_remaining_time`, `search_room_memory`, and `finish_meeting`. The model never supplies room, session, or occurrence identifiers; all proposed mutations are validated by the controller.

## Role behavior

- Scrum Master: recall prior commitments, run a seat-by-seat status round, probe blockers, capture actions, and close with owners and next steps.
- Fun Friday Organizer: choose Auto, Rapid-fire trivia, Would You Rather, or Categories; explain rules, rotate equally, score when relevant, announce results.
- Brainstorm Facilitator: frame the topic, solicit divergent ideas, challenge and combine promising ideas, cluster and prioritize them, and create concrete next steps.
- Sprint Retrospective Facilitator: run a blameless review, identify root causes, and close with at most three owned improvements.
- Project Status Meeting Coordinator: focus updates on changes, milestones, risks, dependencies, decisions, owners, and dates.
- Incident Response Coordinator: separate facts from assumptions and keep owned actions focused on restoring service.
- Course Instructor: teach one concept at a time with examples, understanding checks, and next learning steps.
- Workshop Facilitator: explain timed activities, balance participation, and confirm outputs, decisions, and owners.
- Technical Interviewer: run a fair, consistent interview with adaptive questions and structured observations.
- Product Discovery Facilitator: uncover user problems and evidence before solutions, then capture validation work.
- Decision-Making Facilitator: compare options against explicit criteria and capture the decision, rationale, risks, and owner.
- Town Hall Moderator: organize announcements and Q&A, record unanswered questions, and never invent missing answers.
- Custom: apply admin instructions within the same timed, controlled meeting framework.

## Agent implementation

- A regular ADK `Agent` owns each Gemini live session through `Runner.run_live()` and `LiveRequestQueue`, with bidirectional audio, input/output transcription, session resumption, and context-window compression.
- A low-level LiveKit RTC worker forwards only floor-owner PCM16 mono audio to ADK. Normalize browser/LiveKit audio to 16 kHz before placing bounded 80 ms floor-scoped frames on the queue; discard stale frames at every floor generation, send `AudioStreamEnd` after input pauses, and publish Gemini PCM16 24 kHz output to LiveKit on a separate playout task so model event intake is never blocked.
- A facilitator finish request is deferred until ADK marks that model turn complete, the worker's generated-frame queue drains, and LiveKit `AudioSource.wait_for_playout()` confirms the native audio queue is empty. Only then does the lifecycle enter `PROCESSING`; a bounded timeout prevents a stuck live session.
- At start inject the immediately previous Firestore recap. Semantic room memory uses Agent Platform Memory Bank with `user_id=room_id`, `session_id=occurrence_id`, and stable seat IDs in facts.
- After a meeting, an ADK 2.x graph Workflow normalizes finalized transcript segments, produces and validates a typed `MeetingRecap`, persists it, and adds explicit decisions/actions/blockers/ideas/commitments to Memory Bank.
- `MeetingRecap`: summary, decisions, actions with optional owner slot, blockers, ideas, and game results.

## Public API

- `POST /v1/rooms`
- `POST /v1/capability-sessions`
- `GET|PATCH|DELETE /v1/rooms/{roomId}`
- `POST /v1/rooms/{roomId}/slots/{slotId}:regenerate`
- `PUT /v1/rooms/{roomId}/slots/{slotId}:end-meeting-permission`
- `POST /v1/rooms/{roomId}:join` and `POST /v1/rooms/{roomId}:refresh`
- `POST /v1/occurrences/{occurrenceId}:start`
- `POST /v1/occurrences/{occurrenceId}:leave` and `POST /v1/occurrences/{occurrenceId}:end`
- participant recap and admin history/transcript endpoints
- authenticated Pub/Sub push endpoints for post-processing and cleanup

LiveKit data envelope: `{v, type, occurrenceId, sequence, payload}` with `meeting.state`, `hand.raise`, `caption.final`, and `recap.ready`.

## UI

- Admin creation wizard; copy/revoke links; delegate/revoke end-meeting control; end an active meeting for everyone; meeting state; 90-day history/transcripts.
- Participant capability exchange, consent/device-check lobby, meeting stage, timer, current speaker, roster, hand raise, mic state, leave/end controls, live captions, and recap. A successful microphone check is remembered on that browser while permission remains granted; blocked or unavailable access requires a new check.
- Deep navy/indigo foundation, mint/coral status accents, mobile/desktop responsive design, keyboard navigation, reduced motion, live regions, and WCAG 2.2 AA contrast.

## Operations and infrastructure

- Terraform provisions APIs, VPC, zonal GKE Standard in `europe-west4-a`, a dedicated public media node pool and separate worker pool, regional named Firestore with delete protection, Artifact Registry, Pub/Sub/DLQ/push subscriptions, Scheduler, Secret Manager with user-managed European replication, Redis, service accounts/IAM/Workload Identity, Cloud Run services/jobs, monitoring, and supporting IP/DNS/cert configuration.
- Control and live-worker completion paths immediately publish the occurrence's idempotent transactional outbox record to reduce recap latency. The one-minute scheduler remains the retry/reconciliation backstop.
- LiveKit is one host-networked pod per media node. Expose signaling TLS plus 7881/TCP, 50000-60000/UDP, 3478/UDP, and 5349/TCP. Dev starts at one media node and two workers; autoscale to three/six.
- Web uses its Cloud Run `run.app` URL. LiveKit/TURN use reserved addresses with disposable `sslip.io` names.
- Rate limits start at five room creations/IP/hour and twenty failed capability exchanges/IP/minute.
- Retain transcripts, recaps, and Memory Bank facts for 90 days. A daily reconciliation job removes expired Firestore, Agent Session, and Memory Bank data; expiry fields are backstops.
- Redacted structured logging and Cloud Trace/Monitoring cover active meetings, joins, latency, audio gaps, reconnects, worker health, and stuck processing. Set `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=false`.

## Verification and deployment gate

- Unit: normalization/uniqueness, validation, capabilities/revocation, occurrence transaction, grace/timer/floor, duplicate seats, tool authorization/idempotency, audio conversion, final captions, retention, outbox.
- Integration: Firestore emulator, local LiveKit, fake ADK; lifecycle/floor isolation, reconnect handling, and two-session stable-seat memory and expiry.
- Agent eval: all twelve presets plus Custom, edge cases, unsupported-claim handling, and safety; normalized quality >= 0.8 and zero deterministic authorization/isolation failures. Run in EU or with a local evaluator calling the EU model.
- End-to-end/load assets: Playwright synthetic microphones and five concurrent ten-person synthetic-media rooms; one short deployed real-model smoke test only after approval.
- Acceptance: no raw audio persistence, zero cross-room memory access, join p95 <5s, end-of-turn to agent audio p95 <2.5s in-region, reconnect <10s.
- Before provisioning, produce `terraform validate`, a reviewed saved plan/resource list, and current monthly cost estimate, then stop for explicit approval. Do not run `terraform apply`, deploy containers, create/update cloud resources, or trigger live-model tests before that approval.
